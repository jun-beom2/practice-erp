# 연습용 ERP (사내 ERP 흉내) — F12·자동화 연습용

> ⚠️ **연습용 가짜 ERP입니다.** 거래처·품번·수량은 전부 가상·더미 — 실제 회사 데이터가 아닙니다. 그래서 캡처·저장 다 마음껏 해도 안전합니다.

블록 ②③에서 **F12로 응답 보기 → 자동화(조회 → 입력 → 저장 직전 멈춤)** 를 안전하게 연습하는 사이트입니다.
(블록 ①의 F12 기초는 네이버 같은 익숙한 사이트에서, 블록 ④는 진짜 ERP에서.)

## 여는 법 — 반드시 프록시 서버로
F12 Network에 프록시 응답과 저장 요청이 보이려면 **프록시 서버**로 열어야 합니다. (더블클릭 `file://` 로 열면 데이터가 안 옵니다.)

- Codex에: **"이 연습ERP 폴더에서 프록시 서버 열어줘"**
- 또는 터미널에서 이 폴더로 이동 후 `python proxy_server.py` → 브라우저에서 `http://localhost:8000/`

## 화면
- `index.html` — **발주조회**: [조회] 버튼 → 프록시가 `api/orders.json`을 대신 받아 표로 표시. (F12 → Network → `proxy/orders` → `fetch로 복사` + Response 확인)
- `input.html` — **납품입력**: 발주 하나 골라 납품수량 입력 → 저장 직전 멈춤. 선택 실습에서만 [저장]을 눌러 `api/deliveries` 더미 POST 요청을 봅니다.

## 이 사이트로 익히는 핵심 흐름
1. **F12로 응답 보기** — `orders.json`이 어떤 데이터인지 눈으로 확인 (정리표 = JSON).
2. **프록시(심부름꾼)로 응답 가져오기** — `/proxy/orders`가 대신 다녀와 데이터를 받아옴.
3. **RPA(로봇 손)처럼 화면 구동** — 조회·납품수량 입력을 사람처럼. **저장 직전 멈춤.**
4. **선택 실습: 더미 저장 요청 보기** — 연습 ERP에서만 `api/deliveries` POST 요청의 Payload를 F12로 확인.

## F12 Network에서 무엇을 복사해야 하나
자동화에는 응답 데이터만으로는 부족합니다. **어떤 화면에서 무엇을 눌렀고, 어떤 요청이 나갔는지**까지 같이 확인해야 합니다.

- `응답 복사` — 결과 JSON 확인용. 예: `orders` 배열에 발주 데이터가 들어 있는지 확인.
- `fetch로 복사` — 어떤 URL을 어떤 방식으로 호출했는지 확인용. 자동화 설명에는 이 정보가 가장 중요합니다.
- `cURL로 복사` — 터미널이나 다른 도구에서 같은 요청을 재현할 때 사용.
- `HAR로 복사` — 여러 요청의 전체 흐름을 한 번에 볼 때 사용. 단, 파일이 커질 수 있습니다.

조회 버튼 자동화 기준:
1. 화면에서 `[조회]` 버튼을 클릭합니다.
2. Network에서 `proxy/orders` 요청이 발생했는지 확인합니다.
3. `proxy/orders` 항목은 `fetch로 복사`해서 요청 정보를 남깁니다.
4. Response의 `orders` 배열로 조회 결과를 검증합니다.

조회 버튼 셀렉터:
```text
[data-testid="search-button"]
```

납품 저장 자동화 기준:
- `api/deliveries`는 POST 요청이므로 반드시 `fetch로 복사`해서 Payload를 확인합니다.
- 저장 후에는 다시 `proxy/orders`를 조회해서 `납품수량`, `잔량`, `상태`가 바뀌었는지 확인합니다.

## 안전
- 전부 가상 데이터라 선택 실습에서 **저장 요청까지 눌러봐도 안전**합니다. 실제 파일이나 데이터베이스에는 저장하지 않습니다.
- 단, 블록 ④ **진짜 ERP**에서는 입력값을 테스트·더미로, **저장은 사람이 확인 후** 직접.
